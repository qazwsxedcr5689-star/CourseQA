# 数据库系统与操作系统核心讲义

## B+ 树索引原理与聚集索引对比
关系型数据库（如 MySQL InnoDB 与 SQLite）普遍采用 B+ 树作为核心索引结构。与 B 树不同，B+ 树的非叶子节点仅存储键值（Key）和子节点指针而不保存数据记录，因此单个磁盘页（如 16KB）能容纳更多的分支阶数，使得树高通常控制在 3~4 层以内，仅需 3~4 次磁盘 I/O 即可在千万级表中定位数据。

此外，B+ 树的所有叶子节点包含全部关键字及对应数据（或主键引用），且叶子节点之间通过双向链表顺序相连，极为适合高频的范围查询（`BETWEEN`、`>`、`<`）与 `ORDER BY` 顺序扫描，避免了 B 树跨层中序遍历带来的随机磁盘寻道开销。

## 数据库事务 ACID 特性与 MVCC 多版本并发控制
数据库事务必须满足四大 ACID 特性：
- 原子性（Atomicity）：事务操作要么全部成功提交，要么全部失败回滚（依托 Undo Log 实现）。
- 一致性（Consistency）：事务执行前后数据库完整性约束（如外键级联 `ON DELETE CASCADE`、库存非负）保持不被破坏。
- 隔离性（Isolation）：并发事务之间互不干扰，通过锁机制与 MVCC 解决脏读、不可重复读与幻读问题。
- 持久性（Durability）：一旦提交，修改永久生效（依托 Redo Log / WAL 预写式日志实现）。

MVCC（多版本并发控制）通过隐藏列（事务 ID `trx_id` 与回滚指针 `roll_pointer`）配合 ReadView 一致性视图，实现了“读不加锁、读写不冲突”的非阻塞快照读，极大提升了读多写少场景下的数据库并发吞吐量。

## 进程与线程管理及 CPU 调度算法
进程（Process）是操作系统资源分配的基本单位，拥有独立的虚拟地址空间、页表和文件描述符表，进程间切换需刷新页表与 TLB 缓存，上下文切换开销较大；线程（Thread）是 CPU 调度的基本单位，同一进程内的多个线程共享堆内存与全局变量，仅独享栈空间与寄存器，通信高效但需通过互斥锁（Mutex）、信号量（Semaphore）或条件变量防范数据竞争（Race Condition）。

经典 CPU 调度算法包括：先来先服务（FCFS）、短作业优先（SJF，平均等待时间最短但可能导致长作业饥饿）、时间片轮转（Round-Robin，兼顾响应时间公平性）以及多级反馈队列调度（MLFQ，综合优先级与时间片动态升降级）。

## 虚拟内存、缺页中断与 LRU 页面置换算法
虚拟内存通过页表（Page Table）将进程连续的虚拟地址映射至离散的物理页帧，辅以快表（TLB）加速地址转换。当访问的页面不在物理内存中时触发缺页中断（Page Fault），由操作系统从磁盘调入页面。

当物理页帧已满时需执行页面置换算法：最优置换（OPT，理想基准）、先进先出（FIFO，存在 Belady 异常）、最近最少使用（LRU，基于局部性原理置换最长时间未被访问的页面，工业界常使用哈希表 + 双向链表在 O(1) 时间内实现 LRU Cache）以及时钟置换算法（Clock / NRU，近似 LRU 且硬件开销低）。

## 死锁四个必要条件与预防避免策略
系统发生死锁（Deadlock）必须同时满足四个必要条件：互斥条件、请求与保持条件、不可剥夺条件、循环等待条件。处理死锁的工程方法包括：
1. 死锁预防：破坏四个必要条件之一，最实用的是“资源按固定全局编号顺序申请”以破坏循环等待。
2. 死锁避免：在分配资源前使用银行家算法（Banker's Algorithm）检测系统是否处于安全状态（存在安全序列）。
3. 死锁检测与解除：利用资源分配图（RAG）化简算法定期检测环路，发现死锁后通过回滚事务或终止代价最小的进程恢复系统。
